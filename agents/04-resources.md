# Agent 04 — Resource Integration

## Required inputs and references
Working design/brief, base constraints and theme title. Read the [effects index, kit and tool routes](../references/effects.md) in full, then open each recipe file that holds a selected recipe: [text and entrances](../references/effects-text.md), [interaction and icons](../references/effects-interaction.md), [backgrounds, depth and 3D](../references/effects-backgrounds-3d.md), [navigation and loading](../references/effects-navigation-loading.md). Also read [source routes and branding](../references/resources.md), [XML contexts](../references/blogger-language.md#xml-and-escaping-contexts) and [platform limits](../references/blogger-design.md#platform-api-feeds-and-integrations).

## Steps
1. For every row of the design's effect table, open its recipe and take the code from it: markup, CSS and script. Adapt names, colors, sizes and timings to the design plan; keep the structure, the guards and the reduced-motion and phone behavior. Do not rewrite a recipe from memory and do not replace it with a library. Actively consider the full choice index for each requested effect or icon; a simpler recipe being available does not justify silently dropping a richer choice the user made. Select a broad appropriate mix, not everything by default.
2. Assemble the pieces the way the [kit](../references/effects.md#the-kit) describes: one head gate, the kit styles, and one body script holding the phone menu block, then the kit, then each selected recipe. A no-motion brief gets none of this.
3. Load an engine only when a selected recipe is marked CDN, and only from [the pinned list](../references/effects.md#engines-from-a-cdn), with its integrity hash and at most one engine per theme. For a tool the user named that has no browser file, follow its [route](../references/effects.md#tool-routes): the hardcoded recipe is the working equivalent, described as an original recreation. No package/build installation is required or requested.
4. Inspect the exact selected source/API/license and browser entry. Verify versioned URLs and any SRI bytes with available tools. A historical CDN record is evidence with a date, not a guarantee that an endpoint currently works.
5. React/Next source is not a ready browser script. Use an actually available official browser distribution/ES module or an authorized selected-source adaptation. Do not paste JSX, rely on server APIs, invent a CDN or ship a runtime compiler. If those routes are unavailable, disclose the tradeoff and choose a working alternative consistent with the brief.
6. Keep only the recipes, SVG symbols, CSS and initialization actually used; keep the kit itself whole. Prefer one main animation engine. Inline finished code/styles/icons into the XML and reference verified external assets where necessary. Do not create a shipped assets folder, bundle an entire catalog or add npm dependencies to the skill/project.
7. Implement page transitions and genuine loading cues from [their recipes](../references/effects-navigation-loading.md) and under the resource reference's native-navigation rules. Test failure/reset/reduced-motion behavior. Do not promise a true cross-page load percentage that cannot be observed.
8. Prepare a real custom favicon, preferably embedded in XML where compatible. Include required license text inside safe XML/JS/CSS comments. If a scene or hosted asset is missing, do not fake its URL or claim completion; resolve it with the coordinator.

## Outcome and gate
Code handed on must already follow the [syntax conformance pass](../references/blogger-validation.md#syntax-conformance-pass) items for markup, skin and script. Hand off, for each selected effect, its recipe ID, the adapted code, any engine and its version, actual bytes/requests where measured, supported behavior, removed behavior and remaining unknowns internally. An effect with no recipe and no agreed substitute is not ready. No resource-manifest.json, separate notices file or build output is delivered. Each essential selected function has a working route; failed delivery-critical dependencies are not hidden behind “compiled.”
