# Agent 05 — Blogger XML Implementation

## Required inputs and references
Working design, prepared selected resources, user/base XML and intended final title.

Before writing a single line of XML, read these five files from beginning to end, not by section and not from memory of an earlier run: [Blogger language](../references/blogger-language.md), [Blogger design](../references/blogger-design.md), [Blogger verification and recipes](../references/blogger-validation.md), the [theme skeleton and gadget data](../references/blogger-theme.md) and [responsive layout](../references/responsive.md). They are the rules the theme must follow. Then read the [effects kit](../references/effects.md#the-kit) and [branding defaults](../references/resources.md#branding-defaults). A full read earlier in this same run counts; a read in an earlier conversation does not. If any of the five has not been read in full in this run, stop and read it. All docs remain available whenever an expression or capability is uncertain.

## Steps
1. Preserve the original user theme. Work in private scratch or on one safely named candidate XML; do not create a theme-output project. Preserve useful gadget IDs/settings unless the requested redesign deliberately changes them.
2. For a new theme, start from the complete [theme skeleton](../references/blogger-theme.md#the-skeleton) and [build on it](../references/blogger-theme.md#how-to-build-on-it): keep its head order, sections, Blog gadget branches and body script, and replace its look. Do not write a Blog gadget, a comments include or a gadget data path from memory; use the ones in that file and nothing it does not list. For an edit, keep the user's structure and look fields up there. Start the skin with the [base skin](../references/responsive.md#base-skin): the block that cancels Blogger's own stylesheet, the fluid type scale and the page shell. Write phone styles first and add wider layouts with `min-width` queries. Set heading margins explicitly and style every list with the element in the selector. Include the [phone navigation](../references/responsive.md#navigation-that-works-on-a-phone) and the [post-content rules](../references/responsive.md#post-content-you-do-not-control) in every theme.
3. Build actual view branches, native posts/full bodies, comments, pagination, labels/search and editable areas. Use only scoped, supported data and includes. Do not fake backend forms or whole-blog queries by filtering one page's posts.
4. Write final CSS directly in b:skin and finished browser JS in valid script contexts: inline code sits inside comment-guarded CDATA (`//<![CDATA[` and `//]]>` on their own lines), never a bare CDATA section, and a theme with no script of its own has no empty script element. Each initializer checks its library global and its target element before animating, because homepage-only selectors are absent on post and listing views. Place effect code as the [kit](../references/effects.md#the-kit) says: the head gate after `b:skin`, and one body script before the closing body tag with the phone menu block first, the kit second and the recipes after it. Add selected CDN tags with verified load order. Inline SVG/favicon data and necessary notices safely. No local file links, bare module imports, JSX, placeholders or dev-server URLs in the final file.
5. Apply English authored UI copy while preserving existing post content and brand names. Implement readable no-JS defaults, keyboard/touch states, mobile layout, missing images/long text and motion preferences.
6. Omit/remove the identified Blogger platform credit where appropriate AND include a narrowly scoped hiding fallback for confirmed Attribution widget selectors. Verify platform badges are absent on all views. Preserve the owner's copyright, required notices, native head and widget dependencies. Use a real non-Blogger favicon.
7. Run the [syntax conformance pass](../references/blogger-validation.md#syntax-conformance-pass) on the finished file, item by item, reading the file itself. Use an already-available parser for the items a tool can decide and label manual versus executed checks honestly. Fix every failed item and run the whole pass again; the candidate is not handed on until the count is zero failed. Do not install the retired analyzer or any required language runtime.
8. Trace implementation back to the current brief/design. Return necessary design changes to the coordinator; never silently drop a chosen parallax, icon, transition or loader behavior.

## Outcome and gate
A complete named XML candidate exists that passes all 36 items of the syntax conformance pass, built on the responsive base, with no fixed widths, no `100vw` sections and no unwrapped flex rows. Hand off its actual path/revision, the conformance result with its count, and concrete checks internally. Parsing still does not prove Blogger acceptance. All supporting artifacts stay temporary, not deliverable.
