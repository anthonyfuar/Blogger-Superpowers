# Agent 06 — Verification

## Required inputs and references
The actual current XML and internal design/brief/resource notes. Read [full verification/diagnostic matrix](../references/blogger-validation.md), the [responsive contract and check](../references/responsive.md), the [effect checks](../references/effects.md#checking-an-effect), [design/performance](../references/blogger-design.md) and [resource-specific behavior](../references/resources.md). Inspect artifacts yourself rather than accepting another agent's success claim.

## Steps
1. Match evidence to the current revision. Run the [syntax conformance pass](../references/blogger-validation.md#syntax-conformance-pass) again from the file itself, without relying on the implementation stage's result; a difference between the two results is a defect to resolve. Inspect namespace/structure, native widget coverage, complete local asset inlining, real CDN URLs, preserved licensing and absence of development leftovers such as empty scripts. Check each inline script as raw text between its tags, the way the served HTML page delivers it: CDATA markers must be behind `//` comments and the code must still parse. An XML-parsed preview strips CDATA and cannot show this defect.
2. Review the design contract's tokens/contrast/states. Run checks already available in the environment; no installation is required. State manual inspection, parser execution and browser tests separately.
3. Responsive check, required for every theme. With browser tools, run the [overflow check](../references/responsive.md#checking) at 320, 375, 768, 1024 and 1280 px on the homepage, a post, a static page, a listing and the error view. That full matrix is the target; the homepage and a post at 375 and 1280 px are the least that counts as checked, and every view or width not opened is reported as not_run. Use sample content with a long title, a wide table and a post without an image. Any sideways scroll, hidden navigation or cut-off text is a defect to fix, not a note. A theme XML cannot be opened in a browser: build the views as [building a local preview](../references/blogger-validation.md#building-a-local-preview) describes, with Blogger's own stylesheet ahead of the skin and its sample content, so the preview does not flatter the theme. Without browser tools, review the skin against the contract and the Never list and record the check as not_run.
4. With browser tools, exercise keyboard/touch, no JS, a blocked CDN, a stalled CDN, reduced motion, and each selected effect against the [effect checks](../references/effects.md#checking-an-effect), producing each state as the preview section describes. Keep the preview tab in front while watching effects. Inspect console/network and actual screenshots. If tools are unavailable, record not_run, not a fabricated pass.
5. For navigation effects, test normal internal links, anchors, external links, modified/new-tab clicks, downloads, canceled/failed navigation and Back/Forward restoration. Nothing may trap the reader behind a loader or delay navigation for decoration. Real content loaders clear on success/error/timeout and never fake progress.
6. Confirm Blogger platform attribution/badges are hidden, including possible native expansion. Check the favicon separately for competing declarations and default fallback. Keep owner copyright and resource notices. A local hide rule is not a live-blog screenshot.
7. With authorized Blogger access, separately test saving, re-export expansion, public views, comments, pagination, Layout and Customize. Without access, mark those not_run and keep the limitation explicit.
8. Report reproducible defects to the owning role through the coordinator, then rerun affected checks after correction. Do not overwrite another agent's work or repeat unchanged failures without a new hypothesis.
9. For an edit, also compare the result with the original as [editing](../references/editing.md#stage-by-stage) describes: a line diff accounted for change by change, equal structure, and unchanged positions of everything that was not meant to move.
10. Perform the delivery-shape check: one titled XML, no run-created output folder/sidecars/ZIP/source files. All referenced local runtime code and icons must already be inside XML.

## Outcome and gate
Return concise pass/fail/not_run results and evidence internally, starting with the conformance count. Required available local checks and actual discovered defects must be resolved. Missing browser/Blogger access allows an honestly limited local delivery, not a tested or installed claim. Do not deliver validation.md, screenshots or reports unless the user later changes the one-file requirement.
