# Agent 07 — One-File Delivery

## Required inputs and references
Verified current XML, intended creative title and actual check results. Read [installation/recovery and delivery](../references/blogger-validation.md#validation-diagnosis-and-installation) and [branding](../references/resources.md#branding-defaults).

## Steps
1. For an edit, name the file and write the reply as [editing](../references/editing.md#stage-by-stage) describes: the original untouched beside the new file, each change listed, unasked improvements offered separately. Confirm the XML is the verified current revision and reflects the user's choices. Use its agreed brief-derived title as a safe filename: Paper-and-Sun.xml or Midnight-Dispatch.xml are examples, not names to force on unrelated designs.
2. Place that one file in the agreed destination, normally the current project. If the intended filename exists and is not this run's output, choose a clear unique variant; do not overwrite unrelated work.
3. Inspect the file for complete CSS/JS/icon integration and required notices. External verified CDN/hosted media dependencies may remain, but no supporting local files should be needed to upload the theme.
4. Remove only this run's temporary notes, design.md, previews, test files and intermediate assets, unless the user asked to keep the working files. Do not delete user inputs or unrelated folders. The final generated deliverable set is exactly one XML; no theme-output, ZIP, README, manifest, report, screenshot or favicon sidecar is created.
5. In a short English chat response, link the XML, describe the chosen style, explain backup/upload/recovery, and state actual checks and remaining live Blogger work. Give the conformance result in one line. Tell the owner to open the Theme screen's mobile settings and choose to show the desktop theme on phones, because the theme is responsive and Blogger's separate mobile theme would replace it. Say plainly that the theme has not been saved in Blogger, name the gadgets whose starting text the owner should edit in Layout, and ask them to send back the exact message if Blogger refuses the file, so the matching [fallback](../references/blogger-theme.md#if-blogger-refuses-to-save-the-theme) can be applied. No installation document is generated. Be clear about a site-level favicon setting if it remains pending.
6. Return the final path, revision and limits to the coordinator. Publication/upload is not automatic and needs actual authorization/access.

## Completion gate
Exactly one usable, descriptively named XML is delivered, not merely promised. Temporary work is cleaned; user-owned files remain intact. No claim that a theme was saved in Blogger is made without a real result.
